# EduMaterial — Histórias de Usuário

**Versão:** 0.1  
**Status:** Proposta inicial  
**Referência:** `requisitos.md`

## US-001 — Visualizar catálogo

**História**

Como pessoa que procura materiais educacionais, quero visualizar os materiais disponíveis para conhecer minhas opções.

**Critérios de aceitação**

- [ ] O sistema apresenta os materiais cadastrados.
- [ ] Cada item apresenta pelo menos um título.
- [ ] Quando não houver materiais cadastrados, o sistema informa que o catálogo está vazio.

## US-002 — Pesquisar materiais

**História**

Como pessoa que procura materiais educacionais, quero pesquisar por palavras-chave para encontrar recursos relacionados ao assunto desejado.

**Critérios de aceitação**

- [ ] O sistema permite informar uma palavra ou expressão.
- [ ] A pesquisa retorna os materiais correspondentes aos termos informados.
- [ ] A pesquisa sem correspondências apresenta uma mensagem informativa.
- [ ] O usuário consegue realizar uma nova pesquisa após visualizar os resultados.

## US-003 — Consultar detalhes de um material

**História**

Como pessoa que procura materiais educacionais, quero consultar informações sobre um material para avaliar se ele atende à minha necessidade.

**Critérios de aceitação**

- [ ] O material apresenta um título identificável.
- [ ] O sistema apresenta as informações disponíveis sobre o recurso.
- [ ] O usuário consegue identificar qual material está consultando.

## US-004 — Refinar a busca

**História**

Como pessoa que procura materiais educacionais, quero filtrar os resultados para localizar recursos mais adequados ao que preciso.

**Critérios de aceitação**

- [ ] O sistema apresenta os filtros definidos para o MVP.
- [ ] A aplicação atualiza os resultados de acordo com os filtros selecionados.
- [ ] O usuário consegue retirar os filtros aplicados.

**Observação:** esta história está proposta para o MVP, mas sua prioridade e implementação dependem da definição final do escopo.

## Observação metodológica

Estas histórias e seus critérios foram elaborados para um estudo de caso simulado. Eles descrevem comportamentos esperados e servirão de referência para o desenvolvimento e os testes de QA. Não representam funcionalidades já implementadas ou validadas com usuários reais.
